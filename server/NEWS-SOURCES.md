## Retrieval and normalization

- Honest `aiweather/1.0 (+https://aiweather.synteq.app)` UA, one 10-second timeout per read, maximum 4 MiB decoded body. No JS execution, authentication, CAPTCHA/Cloudflare bypass, alternative UA or third-party sources. Passive Cloudflare analytics/JSD or CAPTCHA configuration on a readable listing is not itself an access challenge. HTTP 403 and actual challenges return empty news with a note, even after earlier success.
- RSS/Atom and HTML use Cheerio’s slim DOM/XML parser, not regex markup extraction. RSS 2/RDF, Atom and JSON Feed are supported. There is no verified live JSON Feed among these 48 sources; JSON Feed tests use an explicitly synthetic fixture. HTML recipes are source-specific and recorded.
- Preserve original headline text (decode markup entities and normalize rendered HTML whitespace), official article URLs, and source publication dates normalized to ISO. Calendar dates are midnight UTC, not an asserted publication hour. Atom uses `published`, falling back to the source’s `updated` when no publication field exists. Undated items omit `publishedAt` and follow dated items in original source order.
- Descriptions are optional, supplied by the source only, HTML stripped, capped at 200 Unicode characters. Never synthesize descriptions from full article content. Missing title/link, non-HTTP(S), credential-bearing, and non-official-host links are dropped; deduplicate official URLs, sort newest first, retain ten.
- Fixtures in `fixtures/news/` are recorded official responses with scripts/styles/media omitted for HTML and at most twelve entries for feeds. The manifest records fetch URL, status, original SHA-256/size, recording time and pinned normalized expectations. Synthetic edge-case fixtures are clearly marked. Fixture bodies are not runtime fallbacks.

## Cache operation

At boot, both services seed honest empty pending responses before the server listens, then warm all companies on one four-slot work queue shared with the status poller. Requests never wait on upstream once an entry exists, including the pending startup copy. Uptime success TTL is 30 minutes, news 60 minutes; a one-minute scheduler refreshes expired entries without traffic. Completion time starts the TTL. Refreshes coalesce per company. Failures retry after five minutes or a longer `Retry-After`; ordinary refresh failures retain last successful data/timestamp with an explanatory note. A blocked news source must instead return empty items.

Normalized uptime cache bounds are 2 MiB/company and 8 MiB total; news 128 KiB/company and 4 MiB total. Uptime/news do not retain raw HTTP bodies. The pre-existing status poller runs normally and is included in the live RSS measurement. Production `npm start` constrains V8 old space to 80 MiB and semi-space to 4 MiB; the default unconstrained heap retained too much temporary HTML parsing memory during the initial measurement. Use the production start command (or the same Node flags) when reproducing the RSS results.

`GET /api/news`, `/api/news/:companyId`, `/api/uptime`, and `/api/uptime/:id` return `cache-control: public, max-age=60`. Bulk arrays follow registry order. Unknown ids return JSON 404. Shared contracts and frontend sources are unchanged.
